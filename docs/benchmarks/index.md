# Benchmarks

Every number WARM publishes traces to a committed file under
[`benchmarks/results/`](https://github.com/writerslogic/warm/tree/main/benchmarks/results). These are
single machines and stated protocols, not a substitute for testing your own data. Wins and losses
are listed together.

## Comparison tables

[COMPARISON.md](COMPARISON.md) is generated by `warm-bench table` from
`benchmarks/results/competitive/` and is never edited by hand. Each cell is indexed to its source
file and key path in [comparison.cells.json](comparison.cells.json). Rows are never compared across
hardware classes: each section is one dataset on one hardware class. A verdict is WIN or LOSS only
when a 95% (Bonferroni-adjusted) percentile bootstrap interval of the ratio excludes parity.

```sh
./benchmarks/competitive/warm-bench list            # systems and suites
./benchmarks/competitive/warm-bench install         # pinned comparator environments
./benchmarks/competitive/warm-bench run ...         # run a suite; writes benchmarks/results/competitive/
./benchmarks/competitive/warm-bench table           # regenerate the tables from committed results
./benchmarks/competitive/warm-bench table --check   # fail if the generated files are stale
```

Retain the raw result with its hardware class, then regenerate the table and submit both.

### JavaScript: WARM and Vectra

`warm-bench js` compares `warm-memory` with Vectra (`vectra`, npm), both called in-process from Node, on the text datasets of the
lexical protocol (SciFact, NFCorpus, LongMemEval-dev sessions; FiQA is supported by the command but its committed run is pending, because embedding its 57,638 documents takes about 3.5 hours on the 8-core host). Both index the same 384-dimension document vectors from one file
(WARM's local embedder, embedded once by `examples/competitive_hybrid embed`) and answer with the same query vectors, so the
comparison is the stores. Rows: exact cosine top 10 (`warm-memory/vectra` against `LocalIndex.queryItems`), hybrid (WARM's fused BM25 and
cosine against Vectra's `isBm25` option, which appends BM25 hits after the semantic list and rebuilds its engine per query, so it runs on a
10-query sample per round) and keyword only (Vectra has none). Package versions are pinned exactly in
`benchmarks/competitive/js/package.json` and recorded in each results file (`kind: js`). Set `WARM_MEMORY_DIR` to a checkout built with `npm run build` to measure WARM from source instead of the pinned npm package; the results then record the source commit (`commit`) and the harness commit (`harness_commit`).

```sh
(cd benchmarks/competitive/js && npm ci)
cargo build --release --example competitive_hybrid --features local-embed-download
./benchmarks/competitive/warm-bench js --datasets scifact nfcorpus memory fiqa --embed-bin target/release/examples/competitive_hybrid --rounds 10 --build-repeats 8
```

## Limits of the claims

- Capacity and scaling numbers are sweeps over a tested range, not guarantees. Nothing is claimed
  past the largest value tested.
- Comparisons use each system's default or pinned configuration, and the harness records the
  comparator versions. A result on one machine is not a result on another.
- Regenerate the relevant results file when a change moves the numbers; do not update prose to match
  a remembered figure.
