# H-B-4 primitive accounting

This is a conditional cost model, not a performance measurement. Source is WARM `74bb9fa8`; arithmetic inputs and the runbook hash are in `b4-cost-model.json`.

The final runbook contains 640 searches of 10,000 queries. Summing active row counts gives 3,213,966,138 row-searches and therefore 32,139,661,380,000 point/query pairs. Range lengths reproduce the committed report's live-count accounting; this calculation is not an independent live-membership audit.

E4's 18.208 code bytes per pair are not necessarily 18.208 DRAM bytes. Reusing codes over a query tile can amortize loads, but it does not eliminate the roughly 1.17e15 coordinate-dependent lower-bound evaluations. WARM already performs list-major scanning and eight-query code sharing (`partition.rs:1320-1455`, `QB` at583). The FastScan representation already scans32 codes at once and fuses admission (`fastscan.rs:4-10,49-79`). A claim that batching alone rescues E4 would duplicate existing work and ignore arithmetic. That proposed explanation is rejected.

The different mechanism is a dense integer matrix product with a certificate epilogue. Represent each source vector as an eight-bit integer vector times one scalar; retain the source-derived reconstruction error norm. The triangle inequality then bounds original L2 distance using the reconstructed distance and the two errors. This replaces dimension-wise interval gathers with packed integer dot products. Existing `kernels.rs:698-777` has query/byte-dot kernels; a packed many-query kernel and a conservative original-distance epilogue are not present in the inspected path. `ivf.rs:116-135,680-705` bounds quantized scores and cannot by itself certify distance to the original float vector.

The arithmetic ceiling assumes four physical cores at2.8GHz, two512-bit byte-dot instructions per core/cycle, and64 byte multiplies plus accumulates per instruction. That yields2.867TOPS and2241.9seconds for full100D products. The four-core topology is evidenced by `benchmarks/results/azure/az1-2026-11-09/hardware.txt:14-16`; two-instruction issue rate and sustained frequency are optimistic assumptions. Intel's [third-generation tuning guide](https://www.intel.com/content/www/us/en/developer/articles/guide/deep-learning-with-avx512-and-dl-boost.html) establishes byte-width and VNNI support, but does not certify this workload's sustained issue rate. Eight virtual CPUs must not be counted as eight physical cores.

The serving gate is at least10.713billion fully processed point/query pairs per second, including conversion, scaling, conservative bound comparison and candidate admission. This budgets3000seconds for search, leaving600seconds for seeding, updates, harness overhead and variation. The threshold epilogue may consume all remaining headroom. Padding100 dimensions to128 adds28% to the main work and threatens the model. Full matrix materialization is forbidden: results must remain in bounded tiles. A64-query tile implies approximately50.46TB of code traffic if each tile reloads every code; arithmetic and memory can overlap, but this is not free traffic or a measured bandwidth bound.

At maximum live count10,292,043, raw floats,100-byte codes and projected16-byte metadata total5.311GB. IDs, allocator growth, packing scratch, query tiles, harness and concurrent reclamation are additional. Retaining all30M source vectors would cost12GB raw and violate the8GiB cap. Live-only reclamation makes the minimal representation plausible without establishing end-to-end memory feasibility.

The first numerical counter uses a forbidden-for-serving oracle kth threshold solely as an optimistic rejection test. Serving must obtain an actual upper bound from retrieved candidates; an exact data-only4096-live-row reservoir is one possible seed, costing roughly5.24e12 float operations over the run. Candidate inflation from that seed and stream order remains unmeasured. Adding dense certificates to the existing2865second path would not fit this model: this is a replacement design.

Prior art includes the [VA-file](https://www.vldb.org/conf/1998/p194.pdf) approximation/refinement principle and VNNI matrix arithmetic. [Certified Cosine](https://arxiv.org/abs/1910.02478) offers another proof representation, but assumes an exact nearest-neighbor graph and a unit-sphere metric; WARM's approximate graph and dynamic L2 runbook cannot inherit its certificate without additional construction and metric proofs. No novelty claim is made.

If the fixed reconstruction bound passes the numerical gate, sustainable fused throughput and non-oracle threshold inflation remain separate mandatory gates. Owned hosts can validate counters and implementations; the missing free matched AVX512 host is not permission for paid calibration.
